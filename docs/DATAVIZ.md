# Data visualization doctrine

How charts are built here. The short version: **the form follows the data's
job, colour is computed and validated rather than eyeballed, and no meaning
ever rides on colour alone.**

## Method

1. **Form first.** Magnitude-over-time → dot/lollipop timeline. State →
   status board with labeled chips. Exact values → a real `<table>` (always
   present alongside any chart — it is the accessibility fallback and the
   JS-off tooltip substitute).
2. **Build-time rendering.** All charts are inline SVG generated by
   `tools/build_site.py` in CI. No charting library, no runtime JS
   dependency — the browser gets finished geometry. This is what keeps the
   page inside ADR 0002's 50 KB / JS-off budget.
3. **One axis, one hue per job.** Event marks use the single accent
   (`--link` blue); severity uses the status palette; magnitude maps to
   position and size, never to a rainbow. No dual axes, ever.
4. **Colour is validated, not admired.** Any palette change must be run
   through a CVD/contrast validator (OKLab ΔE across deutan/protan/tritan
   simulations + contrast vs surface) in light *and* dark mode before merge.
   Record the numbers in the PR.

## The measured correction behind ADR 0004

The original choice for `offline` was magenta (#d02670) — "outside the
hazard scale". Validation proved the intent wrong in the way that matters
most: magenta vs danger red **#da1e28 measured ΔE ≈ 9 (normal vision and
deutan alike)** — below the ΔE 15 legibility floor. The state whose entire
purpose is *never be mistaken for danger* was optically adjacent to danger.
Every magenta step failed (best: ΔE 14.5). Purple passed decisively:

| Pair (light) | ΔE normal | ΔE worst-CVD |
|---|---|---|
| magenta #d02670 vs red #da1e28 | 9.2 | 9.0 (deutan) |
| **purple #8a3ffc vs red #da1e28** | **34.0** | **32.3 (protan)** |

So: **`offline` is purple** (#8a3ffc light / #be95ff dark), and `unverified`
took magenta. Full corrected set (light: green #198038, amber #f1c21b,
orange #ff832b, red #da1e28, purple #8a3ffc): CVD separation and
normal-vision floor **pass** on all adjacent pairs; the residual flags are
the inherent ones for any status palette — amber is light on white
(contrast 1.64) and amber/orange sit ΔE 9.3 apart under deutan — which is
exactly why the next rule exists and is mandatory, not advisory.

## Non-negotiables

- **Label + shape, always.** `● NORMAL`, `▲ WATCH`, `◆ WARNING`,
  `■ DANGER`, `⊘ OFFLINE`, `✱ UNVERIFIED`. A status colour without its
  glyph and word is a defect wherever it appears.
- **Status colours are reserved.** Never reused as chart series colours.
- **Amber and orange never appear as unlabeled fills on light surfaces**
  (they fail 3:1 contrast); they appear in chips with borders and text, or
  as marks with direct labels.
- **Text wears text tokens**, never the series colour.
- **A table view accompanies every chart.** Exact values live there; the
  chart shows shape, not precision.
- **Dark mode is its own validated palette** (see `web/tokens.css`), not an
  automatic inversion.
- **Unverified data is badged at the point of rendering.** A chart may not
  launder an unverified figure into looking official; the `✱` travels with
  the number.
